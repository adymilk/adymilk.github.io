我是谁

我是王恒（James），1995 年生，现居上海。

这个网站是我的作品集，也是我的在线简历。如果你在找
Forward Deployed Engineer（前沿部署工程师） 方向的人，
欢迎直接看 作品与证据 和 简历。

我的定位是工业软件与智能制造领域的复合型技术产品负责人。

长期做的是制造业质量数字化这条线：SPC 统计过程控制、MSA 测量系统分析、
过程能力分析（CPK/PPK）、工业数据采集，以及承载它们的企业级 B/S 系统。
参与建设的产品线包括 BSA 工业制造智能数据分析平台下的 BSA-SPC、BSA-MSA，
以及把统计分析能力 API 化的 BQL。

客户现场的数据往往散在 SQL Server / Oracle / MES / ERP 里，设备侧又是
PLC / CMM / SCADA 和一堆工业协议 —— 把这些接通并让质量工程师真的用起来，
是这件事里最难也最有意思的部分。

我认为自己相对少见的地方是能力链条比较完整：
客户需求 → 产品方案 → 系统架构 → 算法与数据接入 → 研发落地 → 客户交付。
这条链上的每一段我都实际做过 —— 既懂质量工程师在关心什么，
也能动手把统计分析引擎接进 Web 系统。

那条最有价值的取舍我单独写了一篇 ——
FDE 的第一性问题：在写代码之前划定边界，
包括我当年漏掉的那一个。

技术方向

  • 工业质量分析 —— SPC（Xbar-R / Xbar-S / I-MR / P / NP / C / U）、
    MSA（Gage R&R、稳定性、偏倚、线性、属性一致性）、CPK / PPK、
    判异规则（Shewhart / Western Electric / Nelson）。
    这是我最深的纵深：X̄ 控制图的公式谁都会写，难的是知道哪种异常判定
    才是客户质量体系真正在用的那个    。
  • 工业数据接入 —— 六种数据库（SQL Server / MySQL / Oracle /
    PostgreSQL / MES / ERP）+ 现场侧（PLC / CMM / 传感器 / SCADA）+
    通信（MQTT / OPC-UA / TCP / UDP / HTTP）。
    真正的难点不是「支持多少种协议」，是在客户内网、离线、权限受限的
    环境里还能把它跑起来。
  • 全栈交付 —— Python / FastAPI、PHP / Laravel、React，从接口、
    数据建模到前端页面能一个人走完。
  • 对可靠性较真 —— 一个能跑的实现和一个被相信的实现之间隔着很远。
    我现在会更早地问「它怎么失败、失败了谁知道」。

关于 FDE 这个角色，我的判断是：技术能力是入场券，在写代码之前划定边界的
能力才是区分度。 这也是我把作品集按「决策链」而不是「技术栈」来组织的原因。

我在做什么

当前主要精力在补齐 LLM / GenAI 方向的工程能力，重点放在
评测（evaluation） 上 —— 我发现大多数演示止步于「能回答问题」，
而真正难、也真正稀缺的是证明它在多大比例上是可靠的。

这件事和我的既有背景是接得上的：工业质量体系本身就是一套关于
「怎么测量、怎么判定异常、怎么设定控制限」的成熟方法论。
把同一套思路用到 LLM 系统上，是我目前最感兴趣的方向。
